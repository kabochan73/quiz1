# 01. 要件定義

## 1. コンセプト

### 何を作るか
自作の記述式問題を **クイズ（問題セット）** としてまとめ、それを解いた回答を
**Claude API がルーブリック採点する** 学習アプリ。1クイズは **1〜30問** で構成する。

### 想定する使い方（重要）
**「知らない問題を解く」ためのアプリではなく、「一度学んだ内容を自分の言葉で説明できるか」を確かめて記憶を定着させるためのアプリ**
（アクティブリコール / 想起練習）。
- ユーザーは対象分野をすでに学習済みで、問題も自分で作る
- 測りたいのは「思い出して説明できる度合い」であって、新しい知識の正解合わせではない
- だから採点の基準は **ユーザーが定義したルーブリック（=思い出してほしい要点のチェックリスト）** が主役

### なぜ作るか
- **学習目的**: Laravel の基礎（認証・Eloquent・リレーション・キュー・テスト）を一通り固める
- **ポートフォリオ**: 「LLM を採点エンジンとして組み込んだ実用アプリ」として見せられる
- **実用**: 自分の勉強（資格・語学・専門知識）の記憶定着を、記述で確認する

### 差別化ポイント
一般的なクイズアプリは選択式で正誤が自明。本アプリは **自由記述 → AI がルーブリックに沿って部分点とフィードバックを返す** ため、
「なんとなく分かる」を「説明できる」に引き上げ、その定着度を経時で追える。

## 2. 想定ユーザー / 利用シーン

- 利用者は**本人のみ**（マルチテナントは考慮するがログイン必須の単一ユーザー運用）
- クイズ・問題は**すべて本人が自作**（インポート機能は v1 では不要）
- 1回の学習セッション = クイズを1つ選んで全問を記述回答 → 採点結果（合計点 + 問ごとの内訳）を確認 → 弱点を把握

## 3. ユーザーストーリー（v1）

### 認証
- 登録・ログイン・ログアウトができる
- ログインしないとクイズ・回答にアクセスできない

### クイズ / 問題管理
- クイズを作成できる（タイトル / 説明 / カテゴリ / タグ）
- クイズには問題を **1〜30問** 登録できる。0問のクイズは作れない（作成は最初の1問とセット）
- 各問は「問題文 / 採点基準（ルーブリック）/ 難易度」を持つ。1クイズ内で難易度が混在してよい
- 採点基準（ルーブリック）は複数の観点を「観点の説明 + 配点」で登録できる。**これが採点の唯一の基準**
- **模範解答はユーザーが書かない**（後述「採点の基準」）。任意で AI に参考解答を生成させることはできる
- クイズ内の問題は並び替えできる
- カテゴリは**親子構造（サブカテゴリ）**で整理できる（例: `IT資格 > 基本情報 > アルゴリズム`、最大3階層）
- クイズを一覧・検索（カテゴリ・タグで絞り込み）できる。**親カテゴリで絞り込むと配下のサブカテゴリのクイズも含まれる**
- クイズ・問題を編集・削除できる（削除で問題数が0になる操作は不可）
- クイズを「下書き / 公開」で切り替えられる（公開のクイズだけ受験対象。公開には問題1〜30問が必要）

### 受験・採点
- クイズを開いて、全問を記述式で回答して提出する
- 提出すると AI 採点が走り、**クイズ合計点 / 各問の点数 / 観点別の部分点 / 総評フィードバック** が表示される
- 採点は非同期（キュー）で **最大10問ずつまとめて** 実行され、完了までは「採点中 k/N」と表示される（全問終わると合計点が確定）
- 一部の問だけ採点失敗した場合、その問だけ再採点できる
- 同じクイズに何度でも再挑戦でき、各受験が履歴として残る

### 履歴・成績
- 自分の受験履歴を一覧（新しい順、クイズ名・合計点・日時）で見られる
- 履歴の詳細で、そのときの各問の回答文・採点内訳・フィードバックを見返せる
- ダッシュボードでカテゴリ別の平均点（正答率）と直近の点数推移をざっくり確認できる（v1 はトップレベルのカテゴリ単位で集計。子孫の成績を合算して表示）

## 3.5 採点の基準（設計の要）

このアプリは「記憶の定着度を測る」もので、ユーザーは対象分野を学習済み。
**ユーザーが手書きした模範解答を採点の正解基準にはしない。** 理由:

- ユーザーが記憶違いで**誤った模範解答**を登録すると、それを基準に採点され、間違いを強化してしまう
- 「思い出してほしい要点」はルーブリックの観点説明として書けば十分（それを書く行為自体が学習になる）

### v1 の方針

| 要素 | 扱い |
|---|---|
| ルーブリック（観点 + 配点 + 加点条件） | **採点の唯一の絶対基準。** ユーザーが定義 |
| 模範解答（ユーザー手書き） | 廃止。入力欄を作らない |
| 参考解答（AI 生成、任意） | ユーザーが「生成」を押すと AI が問題文＋ルーブリックから参考解答を作り、問題に保存。**採点では「表現の一例」としてのみ渡す**（点数の根拠にしない） |
| 採点時の AI への指示 | 「ルーブリックの観点のみで採点。参考解答は一例であり唯一の正解ではない。受験者の表現が参考解答と違ってもルーブリックを満たせば加点。参考解答に疑問があればフィードバックで指摘」 |

### 一貫性の担保
参考解答は**一度生成したら問題に保存して固定**（毎回の採点で作り直さない）。
これにより、同じクイズに複数回挑戦したときの点数を比較できる。ユーザーは参考解答を編集・再生成でき、
その場合は `reference_version` を上げて、以降の受験と区別する。

## 5. 非機能要件

| 項目 | v1 の方針 |
|---|---|
| パフォーマンス | 採点はキュー投入で即レスポンス。1チャンク（最大10問）5〜30 秒想定。チャンクは並列 |
| コスト | 採点コール（=1チャンク）ごとの入出力トークンを `grading_runs` に記録し、後で集計できるようにする |
| 信頼性 | 採点失敗時は `status = failed` にして再実行ボタンを出す。AI の生レスポンスを保存 |
| セキュリティ | API キーは `.env`。全リソースを `user_id` スコープで制御（Policy） |
| 再現性 | 採点に使ったモデル名・プロンプトバージョンを問の回答ごとに記録 |
| テスト | Pest。AI 呼び出し部分はインターフェース化してフェイク実装でテスト |
| 開発環境 | SQLite で即起動できる。マイグレーション + シーダーでサンプル問題を投入 |

## 6. スコープ外（v1 で「やらないこと」を明示）

- 選択式・穴埋めなど記述以外の問題形式
- ユーザーが手書きする模範解答（誤登録による採点汚染を避けるため廃止）
- 1クイズ 30問超 / 問題を複数クイズで共有（1問は1クイズ専属）
- クイズの途中保存・再開（提出は1セッションで完結）
- 複数人での対戦・ランキング
- 問題のインポート / エクスポート
- 決済・課金
- スマホアプリ / ネイティブ対応
- メール通知

## 7. 用語

| 用語 | 意味 |
|---|---|
| Quiz | 問題セット。1〜30問をまとめる。カテゴリ・タグ・公開フラグを持つ最上位単位 |
| Question | クイズ内の1問。問題文・ルーブリック・難易度・（任意の）AI参考解答を持つ。1問は1クイズ専属 |
| ルーブリック（Rubric） | 採点の唯一の絶対基準。「思い出してほしい要点」のチェックリストをユーザーが定義 |
| 参考解答（Reference Answer） | AI が問題文＋ルーブリックから生成する解答例。任意・問題に保存。採点では一例としてのみ扱い、点数の根拠にしない |
| Criterion（観点） | ルーブリックを構成する単位。「観点の説明 + 配点」。1問に 1〜10 個 |
| QuizAttempt | 1回の受験。クイズ合計点を持つ |
| QuestionAttempt | 受験内の各問の回答と採点結果 |
| GradingRun | 採点 API の1コール分（最大10問をまとめて採点）。モデル名・トークン・生レスポンスを保持 |
| Criterion Score | 観点ごとの獲得点（部分点）とコメント |
| Grader | AI 採点処理。Claude API を呼ぶサービス層。1コールで最大10問をまとめて採点 |
